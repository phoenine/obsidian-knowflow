# 标题结构与图注

恢复网页剪藏时丢失或转错的标题，让 Markdown 标题层级反映文章的内容组织。

## 识别

- 从整篇文章理解结构，识别主章节、子章节和更细的主题。
- 标题可能是普通文本、独立段落、整行加粗、带编号的文本，也可能是已有 Markdown 标题。已有标题也可能层级错误，要参与整体判断。
- 结合语义、位置、后续正文、章节编号和前后主题的关系判断。字数、标点、空行和加粗只是线索，不是认定或排除标题的条件。
- 普通段落、强调句、列表项、图表说明、代码和键值内容不是章节标题。有完整句意、承接上文、描述图像位置或记录结果的行保留正文身份，例如「第一行左边是模型 A」是结果说明。
- 图片附近的短句要区分是章节还是图注；图注保持正文。

## 层级

- 文章名称已由笔记提供，正文主章节用 `##`，子章节用 `###`，再细分用 `####`。
- 相互独立的主章节用同一层级；同一父主题下并列的概念、方法、模块和案例用同一层级。只有明确的从属关系才用更深一级。
- 编号体系是层级线索：`第一部分` 高于 `一、`，`一、` 高于 `（一）`，`（一）` 高于 `1.`，`1.` 高于 `1.1`。混用时以语义为准。
- 从深层标题回到任意上级都合法，例如 `####` 之后直接回到 `##`。向下只能逐级深入。
- 不为形式统一强行增减层级，已经合理的结构保持不变。

## 修改

- 只修改有充分依据的地方；证据不足时保持原文。已经正确的标题不要返回。
- 只改标题标记，不改文字。章节编号由程序处理，抄写时保持原样。
- 不新增原文没有的标题。

## 例子

- `12|为什么 AI 更擅长修改函数式代码？`，后面是对这个问题的展开：`{"type":"format","line":12,"text":"为什么 AI 更擅长修改函数式代码？","level":2}`。
- `30|**这是整个系统中最重要的一个问题。**`，前后都是对同一观点的论述：这是强调句，不返回。
- `40|#### 小结` 是对 `## 三、部署` 整章的总结，前一个标题是 `#### 3.2.1 回滚`：`{"type":"level","line":40,"text":"小结","level":3}`。
- 已有 `## 背景`、`### 目标` 且结构合理：不返回。
